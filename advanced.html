1. What a challenge asks

The challenges are for students who want the top of the mark range. Each one is a real engineering problem. An AI tool can write code for any of them, but whether that code works depends on timing, memory and signal behaviour on the board, and you only find that out by measuring it.

The challenges are not equally hard. Choose up to two. Read what each challenge must do and decide what performance you can measure on your board.

2. What you do for each challenge

  1. Write measurable requirements, with units and boundaries. Choose and justify numerical performance objectives appropriate to the application.
  2. Run the algorithm on the ESP32-S3. A result worked out on a PC and shown as device output does not count.
  3. Build the common serial replay, so that replayed samples go through the same code as real IMU samples. See Serial replay. One replay interface serves both of your challenges.
  4. Run replay tests with stated expected results. Name the supplied replay case, or describe how to recreate your test input. Summarise the actual output in the workbook.
  5. Test on the real sensor. X1 and X2 also need real timing and buffer measurements.
  6. Compare with the baseline given in the description, using the same input. A deliberately weak baseline makes the comparison worthless.
  7. Report your results in the workbook. For each test, give the steps and expected result so the lecturer can repeat it. Record what you observed, including relevant measurements and any limitations.
  8. Explain how to access or observe the challenge in its workbook entry, and show that the rest of the monitor still works.

3. How a challenge is marked

Each challenge is worth up to 5 marks, and only two count. Each challenge is marked half on operation and half on verification through its requirements, tests and recorded results. Meeting a target you set yourself does not automatically earn full marks. We assess the suitability of the objective, achieved performance, and how well the tests let the lecturer reproduce and judge your results. The exact rule for partial credit will be published.

The lecturer checks selected behaviour on the board and may repeat tests with separate replay data.
