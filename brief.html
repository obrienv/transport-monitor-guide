Project brief

Build a monitor for sensitive equipment. Submit the basic monitor first, then extend and retest it. The project is worth 40 marks.

  • Part 1: Basic monitor
  • Part 2: Extended monitor
  • What to submit

Part 1: Basic monitor (10 marks)

Build the nine compulsory features below. Write requirements and tests in the Part 1 workbook. Run the tests on your board and record what happened.

IDWhat the monitor must do
C01Start both sensors and report their health separately.
C02Read temperature and relative humidity from the AHT20.
C03Read acceleration on all three axes from the ICM-20948.
C04Raise environmental alarms below 10 °C, above 28 °C, or above 70% RH. Clear each alarm when a valid reading returns within its limit.
C05Calculate total acceleration magnitude from the three axes in g, including gravity. Indicate an alarm on the TFT and over USB serial above 1.5 g. Clear it on a valid reading at or below 1.5 g.
C07Identify each active alarm cause separately.
C08Report missing sensors and failed or invalid readings as faults. Mark unavailable measurements and use valid readings to establish whether a measurement alarm has cleared.
C09Show live measurements with units, individual sensor health, active alarm causes, faults and unavailable values on the TFT. Choose any readable layout. You can use one or several screens, with or without buttons or a Home screen.
C12Print readable measurements, alarm and fault status and individual sensor health over USB serial.

On the board, test normal operation, one environmental alarm starting and clearing, the acceleration alarm starting and clearing, and one sensor fault. Observe both acceleration alarm states on the TFT and over serial. Use controlled checks for exact boundary values if needed, and state what your physical test showed.

Part 1 marking is provisionally split into requirements (2), observed operation (4), test design (2), and recorded test results (2).

Part 2: Extended monitor (30 marks)

Open the Part 2 workbook. Choose Start from Part 1 on the same browser, or import your Part 1 Markdown. Use your feedback to revise the requirements and tests. Test your additions and repeat relevant Part 1 tests on the final binary, using the final alarm limits and interface. Record fresh results and check whether any optional setup instructions need updating.

Part 2A: Compulsory features (8 marks)

IDFeature
P2-C1Gyroscope measurements. Read angular rate on all three axes and report it with units over USB serial (C03, C12).
P2-C2Static tilt. Measure tilt from a fixed upright reference and report a separate tilt alarm above the default 30° limit (C06, C07).
P2-C3Home and button navigation. Show overall monitoring status, alarms, faults and the health of each sensor on Home. Use D0, D1 and D2 to access measurements, settings and other features (C09, C10). Holding D0 for at least 2 seconds returns to Home from any screen. Monitoring continues while menus are open.
P2-C4Editable alarm limits. Let the user edit the minimum and maximum temperature, maximum humidity, maximum acceleration and maximum tilt. Check proposed values and provide confirm, cancel and restore defaults. Apply confirmed limits to the actual alarms. Restore defaults sets the limits to 10 °C, 28 °C, 70% RH, 1.5 g and 30° (C13).

You can reuse additions you built early. Demonstrate and test them on the Part 2 firmware for Part 2A credit. The 8 marks cover the additions, their integration and repeat testing.

Feature access and testing

For each feature in both parts, write its requirements, how to access or observe it, and tests that check its requirements. Give the exact button presses where needed. In Part 2, start from Home for features you operate. For automatic features, say how to trigger or observe them. Include the return-to-Home check in the navigation tests.

What to submit

For each part, submit three items on Blackboard: your source code, one full merged firmware image (*.ino.merged.bin) and your workbook Markdown. Record your test results and measurements in the workbook. Add setup instructions only if the lecturer needs to do something specific to your submission before running the tests. Deadlines will be announced separately.

Export and check your merged firmware image

Use the same file format as in the Firmware Lab. The merged image packages the flash bootloader, partition table, application and any other flash components required by the build in one file. The similarly named *.ino.bin contains the application component only.

  1. In Arduino IDE, select Sketch → Export Compiled Binary. Then select Sketch → Show Sketch Folder and find *.ino.merged.bin in the board-specific folder under build, as in Stage 3 of the lab.
  2. Use the Stage 7 browser-flashing procedure to check your own exported image. Select the merged file in the first file row, set the flash offset to 0x0, leave the other file rows empty and program the board.
  3. Reset the board and check that the monitor starts and prints the Build ID recorded in the workbook. Submit that merged image and the source used to build it.

Requirements and tests

Write each requirement so another engineer can test it. State the behaviour, values and units, and what happens at a boundary or when data is invalid. Use the feature access entry to say how to reach or observe it. Give each test a starting state, steps and an expected result. Record what actually happened. Write the steps and expected result so the lecturer can repeat the test on your binary and decide whether the requirement is met. A requirement without stated values, or a test the lecturer cannot repeat from your document, earns no verification marks. See the worked example.

The lecturer checks the requirements, test procedures, recorded results and source, and repeats selected tests using your binary. Report partial results and failures as well as successful tests. Detailed partial-credit rules will be issued separately.

Hardware and rules

Use the Adafruit ESP32-S3 Reverse TFT Feather, AHT20 and ICM-20948 on USB power. Use the built-in D0, D1 and D2 buttons for physical input. Leave the boards and wiring unmodified. You may use AI tools and you are responsible for the firmware and evidence you submit.
